## `syscall/impl/enter.hpp`

### namespace `impl`

```c++
namespace impl;
```

enter(number, args...) makes syscall number with exactly the arguments given, 0 to 6, and returns the raw result: -errno on failure (-4095..-1). On linux x86_64, aarch64 and riscv64 it is the trap instruction inlined, one overload per argument count, each binding only its own registers (register variables, so the compiler loads them in place). Memory is clobbered: the kernel reads and writes through pointers. Elsewhere a call into libc's syscall(2), or -errc::not_supported (macOS). Perf (x86_64, getppid, -O2, best of 5x5M): 117.7 ns a call with clang and g++, against 118.7 / 119.6 ns for libc's syscall(2): the kernel round trip dominates; inlining saves the call, errno and the setup of unused registers.

### variable `impl::inline_entry`

```c++
inline constexpr bool inline_entry = true;
```

Whether enter is the trap instruction inlined, rather than a call into libc.
