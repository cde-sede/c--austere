### Errors as values

ca has no exceptions. A function that can fail returns `ca::result<T>`: a T, or a `ca::error` (an int code, 0 meaning success, plus the number of the trace that follows it). Failure is built with `ca::failure{e}`, or `ca::fail(code)`; success is the value itself. Discarding a result is a warning, and in ca's builds an error.

```c++
#include "ca/error.hpp"
#include "ca/fail.hpp"
#include "ca/result.hpp"
#include "ca/sv.hpp"

[[nodiscard]] static auto parse_digit(const char c) noexcept -> ca::result<int> {
	if (c < '0' || c > '9')
		return ca::failure{ca::errc::invalid_argument};
	return c - '0';
}

[[nodiscard]] static auto parse_pair(const ca::sv::str text) noexcept -> ca::result<int> {
	if (text.size() != 2U)
		return ca::fail(ca::errc::invalid_argument.code());
	auto tens = parse_digit(text[0]);
	if (!tens)
		return tens.propagate();
	auto units = parse_digit(text[1]);
	if (!units)
		return units.propagate();
	return *tens * 10 + *units;
}

auto main(void) -> int {
	auto good = parse_pair(ca::sv::str{"42"});
	if (!good || *good != 42)
		return 1;
	auto bad = parse_pair(ca::sv::str{"4x"});
	if (bad || bad.error() != ca::errc::invalid_argument)
		return 2;
	return parse_pair(ca::sv::str{"7"}).value_or(-1) == -1 ? 0 : 3;
}
```

`propagate()` hands the error on as a `ca::failure`, which converts to a result of any value type with the same error type. `ca::result<void>` is success or an error.

### Checked access

`optional` and `result` derive `ca::uncertain`, which enforces one rule: test before you read. A container starts unchecked; `bool`, `has_value()`, `ok()` or `holds()` check it, and any change of its contents unchecks it again. In debug builds an unchecked `*r`, `->` or `value()` fails: at compile time when the optimizer can see it (-O1 and above), otherwise by a trap. Reading an absent value traps in every build. Release builds keep no flag, so the check costs nothing there.

The functions that need no check are the ones that cannot read an absent value: `value_or`, `realize_or`, `match`, comparisons, and the monadic chain.

```c++
#include "ca/error.hpp"
#include "ca/optional.hpp"
#include "ca/result.hpp"

[[nodiscard]] static auto halve(const int n) noexcept -> ca::optional<int> {
	if (n % 2 != 0)
		return ca::nullopt;
	return n / 2;
}

[[nodiscard]] static auto checked_root(const int n) noexcept -> ca::result<int> {
	for (int r = 0; r * r <= n; ++r)
		if (r * r == n)
			return r;
	return ca::failure{ca::errc::out_of_range};
}

auto main(void) -> int {
	const int a = halve(10)
		.and_then([](const int v) noexcept { return halve(v); })
		.transform([](const int v) noexcept { return v + 1; })
		.value_or(0);
	if (a != 0)
		return 1;
	const int b = halve(8).and_then([](const int v) noexcept { return halve(v); }).value_or(0);
	if (b != 2)
		return 2;

	const int c = checked_root(17).match(
		[](const ca::realized<int>& v) noexcept { return *v; },
		[](const ca::error& e) noexcept { return -e.code(); });
	if (c >= 0)
		return 3;

	auto fixed = checked_root(17).except(ca::errc::out_of_range, [](ca::error) noexcept {
		return ca::result<int>{0};
	});
	return fixed && *fixed == 0 ? 0 : 4;
}
```

`match(on_value, on_other)` calls one of two functions: with the `realized` value, or with the error (for `optional`, with nothing). `except(code, f)` recovers from one error and lets the others through; `or_else`, `transform_error` and `or_fail` (optional to result) complete the chain. `ca::realized<T>` is what a checked container converts to: a T that is known to be there, which a function can take to state that its caller already checked.

`raise()` turns a failed result into a trap at once, for code where the error cannot be handled locally: inside a context (`ca::with`, layer 4) the context fails with that error and its trace; outside, the program stops.

`optional<T&>` holds a reference and never binds a temporary; assigning one rebinds it, as in C++26.

### Views

Three views share one shape, a pointer and a size passed in two registers, and differ by what they are for. APIs take views, never a pointer and a size.

- `ca::span<T>`: memory. Buffers, I/O, mappings. A `span<ca::byte>` also views char, signed char and char8_t memory, so text passes where bytes are expected.
- `ca::borrowed_slice<T>`: a sequence of elements, with the slice methods: `prefix`, `suffix`, `sub`, `find`, `find_if`, `contains`, `count`, `starts_with`, `compare`, `fill`, `reverse`. `dynamic_array`, `ca::slice` and `ca::array` share the same methods through it.
- `ca::sv::basic<C>` (`sv::str` for char): text, with Python's read-only str methods.

```c++
#include "ca/borrowed_slice.hpp"
#include "ca/integers.hpp"
#include "ca/span.hpp"

[[nodiscard]] static auto checksum(const ca::span<const ca::byte> data) noexcept -> unsigned {
	unsigned sum = 0U;
	for (ca::usz i = 0U; i < data.size(); ++i)
		sum += data[i];
	return sum;
}

auto main(void) -> int {
	int values[] = {5, 3, 8, 3, 1};
	const ca::borrowed_slice<int> all{values};
	if (all.count(3) != 2U || all.find(8).value_or(99U) != 2U)
		return 1;
	all.sub(1U, 3U).reverse();
	if (values[1] != 3 || values[2] != 8 || values[3] != 3)
		return 2;
	if (all.get(5U))
		return 3;

	char text[] = {'a', 'b', 'c'};
	return checksum(ca::span<char>{text}) == 'a' + 'b' + 'c' ? 0 : 4;
}
```

Constness belongs to the elements: a `span<int>` that is itself const still writes its ints. Cutting functions clamp to the bounds rather than failing; `operator[]` traps out of range in every build, and `get(i)` returns an optional for an index that may be out of range. A view may be built from a temporary only when its elements are const or the temporary is itself a view (`BORROWED`), so a view of a dying container does not compile. Arrays of const code units are refused: a text literal's NUL would come along, and text goes through `ca::sv`.

### Option sets

`ca::option_set<Os...>` is a set of flags as a type: `a | b` is the union, `a & b` the intersection, `~a` the complement and `a & ~b` the difference, all resolved at compile time. Any type with a `domain`, a bit `VALUE` and a `SUPPORTED` flag is an option (`ca::is_option`). The open flags of `ca::fs` (layer 3) are options, so `fs::descriptor` (layer 6) rejects an unsupported or contradictory combination when it compiles.

```c++
#include "ca/fs.hpp"
#include "ca/option_set.hpp"
#include "ca/traits.hpp"

constexpr auto flags = ca::fs::append | ca::fs::cloexec | ca::fs::nonblock;
using without_nonblock = decltype(flags & ~ca::fs::nonblock);

static_assert(without_nonblock::HAS<ca::fs::append_t>);
static_assert(!without_nonblock::HAS<ca::fs::nonblock_t>);
static_assert(ca::is_same<decltype(ca::fs::append | ca::fs::append), ca::option_set<ca::fs::append_t>>);
```

`ca::in_place` selects in-place construction where a type has both a value constructor and one taking constructor arguments.

## `impl/`

Internals of the vocabulary types.

- `access.hpp`: what happens when an uncertain container is misused. `value_accessed_while_absent` and `error_raised` are the cold, out-of-line trap paths of `*r` on a failure and of `result::raise`; before trapping, `leave_error` hands the error to the innermost context so it fails with that error (and its trace) instead of a bare reason. A `ca::error`, or anything with an `error()` member, goes as its code and trace number; any other error type is offered whole to the context, moved when it cannot be copied.
- `unit.hpp`: the empty value type standing for `void` in `result<void, E>`, so one implementation serves both.
- `view_rules.hpp`: the rules every view constructor shares. `is_viewable` allows a view of a temporary only when the elements are const or the temporary is itself a view (it declares `static constexpr bool BORROWED = true`); `is_const_text` names arrays of const code units, which spans and slices refuse because a literal's NUL would come along.

A type of your own that refers to memory it does not own opts into the borrowed rule the same way the views do:

	ca::usz _size;

		return _data;
	}
	[[nodiscard]] auto size(void) const noexcept -> ca::usz {
		return _size;
	}
};

auto main(void) -> int {
	int values[] = {1, 2, 3};

## `io/`

The I/O contracts, as concepts: what a byte sink and a byte source must offer. They live here, below every implementation, so formatting (layer 5) targets any writer without knowing about file descriptors, and the descriptor-backed writers (layer 6) need nothing from formatting.

| Concept | Members |
|---|---|
| `io::is_writer` | `write(span<const byte>) -> result<void>`, `flush() -> result<void>`, `error() const -> error`, `clear_error()` |
| `io::is_windowed_writer` | a writer that also lends its buffer: `window()`, `drain(at)`, `settle(at)` |
| `io::is_reader` | `read(span<byte>) -> result<usz>`, 0 only at end of input |
| `io::is_buffered_reader` | a reader that lends its buffer: `fill() -> result<sv::str>`, `consume(n)` |
| `io::is_stream` | both a reader and a writer |

### Writers report errors twice

Each `write` returns its own result, so a loop can stop as soon as output is impossible. The writer also keeps the first error since it was last checked, sticky: code that writes in many places (a formatter, a logger) can ignore the per-call results and check once. `error()` peeks at the sticky error, `clear_error()` forgets it once handled, and `flush()` writes out what is pending, then returns the sticky error and clears it.

A writer is a plain class with those four members; nothing to derive from. Text passes as bytes, since a `span<const byte>` views char memory:

```c++
#include "ca/error.hpp"
#include "ca/format_to.hpp"
#include "ca/io.hpp"
#include "ca/ok.hpp"
#include "ca/result.hpp"
#include "ca/span.hpp"
#include "ca/sv.hpp"
#include "ca/utility.hpp"

class counting_writer final {
	private:
		ca::usz _bytes{0U};
		ca::error _error{};

	public:
		auto write(const ca::span<const ca::byte> bytes) noexcept -> ca::result<void> {
			_bytes += bytes.size();
			return {};
		}

		auto flush(void) noexcept -> ca::result<void> {
			const ca::error e = ca::exchange(_error, ca::ok);
			if (!e.ok())
				return ca::failure{e};
			return {};
		}

		[[nodiscard]] auto error(void) const noexcept -> ca::error {
			return _error;
		}

		auto clear_error(void) noexcept -> void {
			_error = ca::ok;
		}

		[[nodiscard]] auto bytes(void) const noexcept -> ca::usz {
			return _bytes;
		}
};

static_assert(ca::io::is_writer<counting_writer>);
static_assert(!ca::io::is_windowed_writer<counting_writer>);

auto main(void) -> int {
	counting_writer w;
	if (!w.write(ca::sv::str{"hello"}))
		return 1;
	auto written = ca::format_to(w, "{} + {} = {}", 2, 2, 4);
	if (!written || *written != 9U || w.bytes() != 14U)
		return 2;
	return w.flush() ? 0 : 3;
}
```

### Windowed writers write in place

A plain writer receives each piece of formatted text as a copy. A windowed writer instead lends its own free buffer space: the formatter writes straight into it, and asks for more space with `drain(at)` when the window fills. `settle(at)` then ends the message at `at`, which applies the writer's buffering policy (line buffering on a terminal, for instance). A failed drain ends the message and rolls back what of it had not left the writer. `fd` writers, `string_writer` and `memory_writer` are windowed; `ca::text_writer` (layer 5) is the cursor that drives one.

### Readers

`read(buffer)` fills up to `buffer.size()` bytes and returns how many, 0 only at the end of input. Read errors come back per call; nothing is sticky. A buffered reader lends its buffer instead: `fill()` returns the bytes buffered and not yet consumed, reading more only when there are none, and `consume(n)` marks the first n as read, so a parser works in place.

```c++
#include "ca/io.hpp"
#include "ca/memory_reader.hpp"
#include "ca/sv.hpp"

template <ca::io::is_buffered_reader R>
[[nodiscard]] static auto count_lines(R& reader) noexcept -> ca::usz {
	ca::usz lines = 0U;
	for (;;) {
		auto chunk = reader.fill();
		if (!chunk || chunk->empty())
			return lines;
		lines += chunk->count('\n');
		reader.consume(chunk->size());
	}
}

auto main(void) -> int {
	ca::io::memory_reader reader{ca::sv::str{"one\ntwo\nthree\n"}};
	return count_lines(reader) == 3U ? 0 : 1;
}
```

String views: read-only runs of code units that a view does not own, with Python's read-only str methods. `ca::sv::str` (char, UTF-8 by convention) is the everyday one; every code unit type has its own.

### Splitting and partitioning

`split`, `split_lines` and `partition` follow Python's rules exactly, and allocate nothing: `split` returns a lazy range computing each piece as the loop advances.

- `split()` cuts on runs of white space and drops empty pieces.
- `split(sep)` keeps empty pieces, and yields one empty piece for empty text.
- `split(sep, max)` cuts at most max times, leaving the rest whole in the last piece.
- `split_lines()` cuts on every line boundary ("\r\n" counts as one); `split_lines(true)` keeps the boundaries.
- `partition(sep)` and `partition_last(sep)` give the text before, the separator and the text after; when the separator is missing, `found()` is false.

```c++
#include "ca/sv.hpp"

auto main(void) -> int {
	const ca::sv::str line{"name=ada,age=36,,lang=en"};
	int fields = 0;
	int empty = 0;
	for (const ca::sv::str field : line.split(",")) {
		++fields;
		if (field.empty())
			++empty;
	}
	if (fields != 4 || empty != 1)
		return 1;

	const auto kv = ca::sv::str{"age=36"}.partition("=");
	if (!kv.found() || kv.before() != ca::sv::str{"age"} || kv.after() != ca::sv::str{"36"})
		return 2;

	int words = 0;
	for (const ca::sv::str word : ca::sv::str{"  the quick\tbrown \n fox "}.split()) {
		if (word.empty())
			return 3;
		++words;
	}
	if (words != 4)
		return 4;

	int lines = 0;
	for (const ca::sv::str l : ca::sv::str{"a\r\nb\nc"}.split_lines())
		lines += static_cast<int>(l.size());
	return lines == 3 ? 0 : 5;
}
```

`ca::collect` (layer 5) turns a split into a `dynamic_array` when the pieces must be kept.

### Names that differ from Python

The method set is Python's str where it fits, renamed to snake_case words: `lstrip` and `rstrip` are `strip_start` and `strip_end`, `removeprefix` and `removesuffix` are `strip_prefix` and `strip_suffix`, `rfind` is `find_last`, `rpartition` is `partition_last`, `splitlines` is `split_lines`, and each `isX` is `is_X`. `find` returns an optional index instead of -1. The allocating methods (`upper`, `replace`, `center`, `join`, ...) are on `ca::basic_str`, since a view cannot hold their result.

Character classes (`is_alpha`, `is_space`, ...) and white space are decided per code point by the tables of `ca::unicode`, so `split()` also cuts on non-ASCII spaces. `compare` orders by unsigned code unit, which is code point order for UTF-8 and UTF-32. `operator[]` traps out of range in every build; `get(i)` returns an optional.

## `sv/impl/`

How the string methods are shared. `methods.hpp` defines `sv::impl::methods<T, C>`, a CRTP base that writes every read-only text method once, for any type T with `view() -> sv::basic<C>`: the views themselves, `ca::basic_str` and `ca::inline_str` all derive it, so a method added here appears on every string type at once. The methods return views into the text and never allocate.

`classify.hpp` holds the per-code-point helpers the methods walk with: `point_at` and `point_before` decode one code point forwards or backwards (ASCII without decoding), and `space_at`, `space_before` and `line_break_at` measure a white space code point or a line boundary, 0 when there is none. Walking backwards meets the same code points as walking forwards, so `strip_end` and `split` agree on invalid text.

`forward.hpp` declares `sv::basic` ahead of its definition: the methods use `ca::unicode`, whose functions take views, so the view type must be nameable first.

A type of your own gets the whole text API by deriving the base and providing `view()`:

```c++
#include "ca/sv.hpp"

class token final : public ca::sv::impl::methods<token, char> {
	private:
		ca::sv::str _text;

	public:
		constexpr explicit token(const ca::sv::str text) noexcept
		: _text{text} {
		}

		[[nodiscard]] constexpr auto view(void) const noexcept -> ca::sv::str {
			return _text;
		}
};

static_assert(token{"  if  "}.strip() == ca::sv::str{"if"});
static_assert(token{"while"}.is_identifier());
```

## `unicode/`

`ca::unicode`: Unicode algorithms over string views, constexpr, allocating nothing. The encoding is chosen by the size of the code unit: 1 byte is UTF-8, 2 bytes UTF-16, 4 bytes UTF-32, so one function serves `sv::str`, `sv::u8`, `sv::u16`, `sv::u32` and `sv::wide`.

| Function | Answers |
|---|---|
| `decode(text)` | the first code point with its length and validity, or nothing when empty |
| `encode(point, out)` | writes one code point, returns the units written |
| `encoded_size<C>(point)` | units one code point takes in C's encoding |
| `code_points{text}` | range of the code points, for range-for |
| `count_code_points(text)` | number of code points: Python's `len()` |
| `is_valid(text)`, `find_invalid(text)` | well-formedness, and where it breaks |
| `transcode(text, out, capacity)` | conversion between encodings |
| `transcoded_size<To>(text)` | exact output size of a transcode |
| `properties_of(point)` | the character database entry: classes and case mappings |

### Invalid input

Malformed text never stops an algorithm. Every invalid sequence (overlong forms, surrogates, values past U+10FFFF, truncated sequences, lone continuation bytes) decodes as U+FFFD (`replacement_character`), consuming its maximal valid prefix as Unicode recommends, and encoding a value that is not a scalar value writes U+FFFD. So counting, iterating and transcoding agree on how many code points a text has, and transcoding always produces well-formed output: transcoding to the same encoding sanitizes.

```c++
#include "ca/sv.hpp"
#include "ca/unicode.hpp"

static_assert(ca::unicode::is_valid(ca::sv::u8{u8"héllo"}));
static_assert(ca::unicode::count_code_points(ca::sv::str{"héllo \U0001F600"}) == 7U);
static_assert(ca::unicode::find_invalid(ca::sv::str{"ok\xC0\x80"}).value_or(99U) == 2U);
static_assert(ca::unicode::transcoded_size<char16_t>(ca::sv::str{"a\U0001F600"}) == 3U);
static_assert(ca::unicode::encoded_size<char>(U'€') == 3U);

auto main(void) -> int {
	const ca::sv::str text{"a\xFF\xE2\x82\xAC"};
	char32_t points[4]{};
	ca::usz n = 0U;
	for (const char32_t c : ca::unicode::code_points{text})
		points[n++] = c;
	if (n != 3U || points[0] != U'a' || points[1] != ca::unicode::replacement_character || points[2] != U'€')
		return 1;

	char16_t wide[8]{};
	const auto done = ca::unicode::transcode(ca::sv::str{"\xC3\xA9!"}, wide, 8U);
	if (done.read() != 3U || done.written() != 2U || wide[0] != u'é')
		return 2;

	const auto first = ca::unicode::decode(ca::sv::str{"\xE2\x82\xAC"});
	return first && first->code_point() == U'€' && first->length() == 3U ? 0 : 3;
}
```

`transcode` stops before the first code point that does not fit in the output and never splits one; `read()` then tells where to resume. Size the output exactly with `transcoded_size` to convert in one call. The iterator of `code_points` exposes `decoded()` and `position()`, to tell a real U+FFFD from an invalid sequence and to locate it.

UTF-8 paths skip ASCII 16 bytes at a time: validating, counting and transcoding mostly-ASCII text costs little more than a memchr.

### Character properties

`properties_of(point)` returns the database entry of one code point, generated from the UCD of the Python that ran `make unicode` (currently Unicode 15.0), with the classes Python's str methods use: `is_alpha`, `is_decimal`, `is_digit`, `is_numeric`, `is_space`, `is_printable`, `is_identifier_start`, ... It also holds the case mappings, simple (one code point: `to_upper`, `to_lower`, `to_fold`) and full (`upper()`, `lower()`, `title()`, `fold()`, each a `mapping` of 1 to 3 code points, as sharp s uppercases to "SS"). ASCII costs two table reads, any other code point three.

```c++
#include "ca/unicode.hpp"

static_assert(ca::unicode::properties_of(U'é').is_alpha());
static_assert(ca::unicode::properties_of(U'é').to_upper() == U'É');
static_assert(ca::unicode::properties_of(U'٣').is_decimal());
static_assert(ca::unicode::properties_of(U'　').is_space());
static_assert(ca::unicode::properties_of(U'ß').upper().size() == 2U);
static_assert(ca::unicode::properties_of(U'ß').upper().first() == U'S');
static_assert(!ca::unicode::is_scalar_value(0xD800U));
static_assert(ca::unicode::max_units<char16_t> == 2U);
```

The string methods of `sv::impl::methods` and `basic_str` (`is_alpha`, `split()`, `upper()`, `case_fold()`, ...) are built on these, which is why they agree with Python on non-ASCII text.

## `unicode/impl/`

The machinery under `ca::unicode`.

- `tables.hpp`: the character database, generated by `tooling/gen_unicode.py` (`make unicode`) from the running Python and the UCD of its Unicode version; never edited by hand. Python's own two-stage layout: `block_of[point >> BLOCK_SHIFT]` picks a block of `record_index`, whose entry picks a `char_record`. Code points from `TABLE_LIMIT` up share record 0: no class, mapped to themselves.
- `char_record.hpp`: one record per group of code points sharing properties: class flags, the simple case mappings as deltas (point + delta), and for code points with full mappings the index of their `special_case` (up to three code points per mapping).
- `flags_of.hpp`: the class flags of a code point; `ascii_flags` copies the 128 ASCII entries into one flat array at compile time, so ASCII costs a single read.
- `decode_at.hpp`, `decode_before.hpp`: decode one code point forwards from a position, or the one ending at a position. Decoding backwards splits invalid sequences exactly as decoding forwards would, so a text walked from either end yields the same code points.
- `skip_ascii.hpp`: the fast path of UTF-8 algorithms: the first position, 16 bytes at a time, where a byte at or above 0x80 may sit. In constant evaluation it returns its argument and the scalar loop runs instead.

Regenerating the tables with a newer Python moves the whole library to its Unicode version, and `tooling/gen_str_test.py` then regenerates the test that checks the string methods against that Python.
